# eli5c

将用户指定的主题当成对方完全零基础来讲解，输出一个自包含、排版克制的交互式单文件 HTML Artifact：**纯中文行文、字少直白、无静态配图、内置 1 个可玩微交互演示和 1 道秒懂自测题**。

**禁止**进行前置提问访谈——直接生成 HTML 解释页面。

## 1. 语言与行文规范

- **地道纯中文输出**：哪怕用户输入的是英文技术缩写（如 `/eli5c RAG`、`/eli5c KV Cache`），页面标题、正文、微交互按钮、SVG 标签与自测题也必须全部使用自然、地道的中文。核心英文专有名词首次出现时可在括号内保留原词，如 `检索增强生成（RAG）`。
- **零术语负担与具象表达**：用日常生活中的具体事物打比方，让初学者或 5 岁小孩也能秒懂。必须先讲清楚具体现象和作用，再引出专业名词。
- **去套话与翻译腔（De-slop）**：使用干净利落的中文短句。严禁“从本质上讲”、“简而言之”、“它不仅仅是 X，更是 Y”等空洞套话，禁止堆叠多层副标题。

## 2. 叙事与教学结构

按以下四个节奏组织页面内容：

1. **体感开场（生活体验 → 反常转折 → 点出概念）**：先从读者熟知的日常体验切入，抛出一个有趣的转折或问题，最后再在 `<h1>` / 首屏亮出概念名称。
2. **单一核心类比（One Mental Model）**：尽早引入**唯一一个**直观的生活类比，并作为主线贯穿全文与交互演示，绝不混用多个互相打架的比喻。
3. **3–5 张编号分步卡片（渐进拆解）**：按概念依赖顺序，将工作原理拆解为 3–5 张卡片（`01`、`02`、`03`...），每张卡片控制在 2–3 句简短中文以内。
4. **一句话总结（Takeaway）**：在解释末尾用一句好记的大白话复述核心类比，帮读者锁定记忆。

## 3. 微交互演示与秒懂自测（Show, Don't Tell）

不靠静态插图，而是让读者动手操作来理解机制：

- **1 个可玩微交互演示（Playable Micro-Demo）**：使用原生 JS + HTML/CSS/SVG 构建 **1 个反映真实机制的交互小组件**，让读者改变输入即可实时看到结果变化：
  - 连续滑块（监听 `input` 事件而非 `change`）实时驱动公式计算或图形状态变化
  - 分步状态模拟器（点击「下一步」逐步推进机制状态）
  - 前后对比开关或「先猜后看」互动卡片
  - 控件保持极简，预填合理的初始默认值，所有标签与状态说明均使用简明中文。
- **结尾 1 道秒懂自测题（1-Question Micro-Quiz）**：在页面底部放置 **1 道单选题** 检验理解程度：
  - 点击选项后立即给出明确的文字判定（`✓ 答对了` 或 `✗ 差一点`），绝不只靠红绿边框颜色区分对错。
  - 选中后展示一句话原理解析，并支持重新作答。

## 4. 视觉规范与反 AI 廉价感（Anti-Slop Bar）

- **禁止静态图片**：不生成、不内嵌、不外链任何位图（`<img>`）。仅使用排版、CSS 布局以及微交互所需的干净内联 SVG/Canvas。
- **禁止将 Emoji 当作图标**：严禁在标题、列表、卡片或按钮中使用 Emoji（🚀✨💡🔍📊）充当图标。改用粗体数字序号（`01`、`02`）、CSS 几何图形或极简纯色 SVG。
- **语义化配色与集中式变量**：在 `:root` 中定义 CSS 变量。采用干净的纸张底色、高对比度正文墨色（对比度 `≥ 4.5:1`）以及 **1–2 个有明确语义的强调色**（例如颜色 A 代表输入/原因，颜色 B 代表输出/结果）。禁止彩虹渐变与泛滥的卡片阴影。
- **按钮视觉层级**：主要交互操作（「运行」、「下一步」、「验证答案」）使用实心填充按钮；次要操作（「重置」）使用描边或幽灵按钮。

## 5. 交付前静态自检

在交付 HTML Artifact 前逐项核对：
- [ ] 全页标题、卡片、微交互控件、SVG 标注与自测题均为地道中文，无生硬翻译腔。
- [ ] 页面中无任何 `<img>` 标签，且无装饰性 Emoji 图标。
- [ ] 可玩微交互在页面加载完成时（`DOMContentLoaded`）即渲染好初始帧，拖动或点击时实时响应且无 JS 语法或引号转义报错。
- [ ] 内联 `<svg>` 的 `viewBox` 四周留有至少 `16px` 内边距，确保中文标签在边缘不被裁切。
- [ ] 无任何内容因等待 `IntersectionObserver` 而默认设为 `opacity: 0`，桌面端与移动端打开即可直接看到完整内容。
